    - Follow SessionService pattern but with admin-specific Redis keys:
      - 'admin:session:{admin_id}:{session_id}'
      - 'admin:session:blacklist:{jti}'
      - 'admin:session:admin:{admin_id}'
    - Methods: createSession, revokeSession, revokeAllSessions, isTokenBlacklisted, blacklistToken
    - Session TTL: 8 hours (ADMIN_SESSION_TTL_SECONDS or default 28800)
    - Max sessions per admin: configurable (ADMIN_MAX_SESSIONS or default 5)
    - Inject RedisService and ConfigService

    Create AdminService at api/src/modules/admin/admin.service.ts:
    - Inject: Repository<Admin>, JwtService, AdminSessionService, ConfigService
    - Methods:
      - login(dto: AdminLoginDto, context: { userAgent, ipAddress }): Validate credentials, check lockout, increment failed attempts, create session, return token
      - logout(adminId: string, jti: string): Blacklist token, revoke session
      - validateCredentials(email, password): Find admin by email, compare password with bcrypt
      - findById(id: string): Get admin by ID
      - isTokenBlacklisted(jti: string): Delegate to AdminSessionService
      - checkAndUpdateLockout(admin: Admin): Check if locked, increment attempts if failed, lock if threshold exceeded
    - Lockout configuration: ADMIN_MAX_FAILED_ATTEMPTS (default 5), ADMIN_LOCKOUT_DURATION_MINUTES (default 30)
    - JWT payload: { sub: admin.id, email: admin.email, name: admin.name, iss: 'nebula-admin', jti: uuid, mfaVerified: admin.mfaSetupComplete }

    IMPORTANT:
    - Use bcrypt for password comparison (NOT argon2 - bcrypt is already in use)
    - JWT token must include iss: 'nebula-admin' claim
    - Session keys must use 'admin:' prefix (completely isolated from tenant sessions)
