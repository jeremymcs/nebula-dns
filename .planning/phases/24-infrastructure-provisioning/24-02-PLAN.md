  <action>
Create `infrastructure/terraform/modules/managed-databases/` module.

1. `variables.tf` - Shared variables:
   - `project_name` (string) - Resource name prefix
   - `environment` (string) - Environment name
   - `region` (string, default "nyc3") - DigitalOcean region
   - `vpc_uuid` (string) - VPC to place databases in
   - `postgres_node_size` (string, default "db-s-2vcpu-4gb") - PostgreSQL instance size
   - `postgres_node_count` (number, default 2) - PostgreSQL nodes (2 for HA)
   - `postgres_version` (string, default "16") - PostgreSQL version
   - `postgres_pool_size` (number, default 50) - PgBouncer pool size
   - `postgres_pool_mode` (string, default "transaction") - PgBouncer mode
   - `valkey_node_size` (string, default "db-s-1vcpu-2gb") - Valkey instance size
   - `valkey_node_count` (number, default 2) - Valkey nodes (2 for HA)

2. `postgresql.tf` - PostgreSQL resources:
   ```hcl
   resource "digitalocean_database_cluster" "postgres" {
     name                 = "${var.project_name}-${var.environment}-pg"
     engine               = "pg"
     version              = var.postgres_version
     size                 = var.postgres_node_size
     region               = var.region
     node_count           = var.postgres_node_count
     private_network_uuid = var.vpc_uuid

     maintenance_window {
       day  = "sunday"
       hour = "04:00:00"
     }
   }

   resource "digitalocean_database_db" "nebula" {
     cluster_id = digitalocean_database_cluster.postgres.id
     name       = "nebula"
   }

   resource "digitalocean_database_user" "nebula" {
     cluster_id = digitalocean_database_cluster.postgres.id
     name       = "nebula"
   }

   resource "digitalocean_database_connection_pool" "pgbouncer" {
     cluster_id = digitalocean_database_cluster.postgres.id
     name       = "pgbouncer-pool"
     mode       = var.postgres_pool_mode
     size       = var.postgres_pool_size
     db_name    = digitalocean_database_db.nebula.name
     user       = digitalocean_database_user.nebula.name
   }

   resource "digitalocean_database_firewall" "postgres" {
     cluster_id = digitalocean_database_cluster.postgres.id
     rule {
       type  = "k8s"
       value = var.doks_cluster_id
     }
   }
   ```
   Add `doks_cluster_id` (string) to variables.tf - used by firewall rule to restrict DB access to DOKS cluster only.

3. `valkey.tf` - Valkey resources:
   ```hcl
   resource "digitalocean_database_cluster" "valkey" {
     name                 = "${var.project_name}-${var.environment}-valkey"
     engine               = "valkey"
     version              = "7"
     size                 = var.valkey_node_size
     region               = var.region
     node_count           = var.valkey_node_count
     private_network_uuid = var.vpc_uuid
   }

   resource "digitalocean_database_firewall" "valkey" {
     cluster_id = digitalocean_database_cluster.valkey.id
     rule {
       type  = "k8s"
       value = var.doks_cluster_id
     }
   }
   ```

4. `outputs.tf` - Connection details (all sensitive):
   - `postgres_host` - Direct host
   - `postgres_port` - Direct port
   - `postgres_user` - Username
   - `postgres_password` - Password (sensitive)
   - `postgres_database` - Database name
   - `postgres_connection_uri` - Full connection string via PgBouncer (sensitive): use the pgbouncer connection pool URI
   - `postgres_direct_uri` - Direct connection string for migrations (sensitive): uses cluster host (not pool)
   - `valkey_host` - Valkey host
   - `valkey_port` - Valkey port
   - `valkey_password` - Valkey password (sensitive)
   - `valkey_connection_uri` - Full connection string with TLS (sensitive): format `rediss://:${password}@${host}:${port}` (note `rediss://` for TLS)
   - `valkey_tls_enabled` - Boolean, always true for managed Valkey

All files must include the copyright header as HCL comments.
