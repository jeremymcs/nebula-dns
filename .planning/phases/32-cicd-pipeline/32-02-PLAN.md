  <action>
Create `.github/workflows/deploy.yml` — the main deployment pipeline.

**Triggers:**
```yaml
on:
  push:
    branches: [main]
  workflow_dispatch:
    inputs:
      skip_tests:
        description: 'Skip test gates (emergency deploys only)'
        required: false
        default: false
        type: boolean
      environment:
        description: 'Target environment'
        required: false
        default: 'staging'
        type: choice
        options:
          - staging
          - production
```

**Environment Variables:**
```yaml
env:
  DOCR_REGISTRY: registry.digitalocean.com/nebula-dns
```

**Job Structure (in order):**

1. **run-tests** — Reuse existing ci.yml as test gate
   - `uses: ./.github/workflows/ci.yml`
   - Add `if: ${{ !inputs.skip_tests }}` to allow emergency bypasses
   - This runs all unit tests, integration tests, E2E tests from ci.yml

2. **run-security-scan** — Reuse existing security-scan.yml
   - `uses: ./.github/workflows/security-scan.yml`
   - `if: ${{ !inputs.skip_tests }}`

3. **build-api** — Build and push API image (parallel with other builds)
   - `needs: [run-tests, run-security-scan]` (or empty if skip_tests)
   - `if: always() && (needs.run-tests.result == 'success' || inputs.skip_tests)`
   - `uses: ./.github/workflows/_build-push-image.yml`
   - `with: { service: api, context: ./api, registry: $DOCR_REGISTRY, image_name: nebula-dns-api }`
   - `secrets: { DIGITALOCEAN_ACCESS_TOKEN: ${{ secrets.DIGITALOCEAN_ACCESS_TOKEN }} }`

4. **build-ui** — Same pattern, `service: ui, context: ./ui, image_name: nebula-dns-ui`

5. **build-admin-ui** — Same pattern, `service: admin-ui, context: ./admin-ui, image_name: nebula-dns-admin-ui`

6. **build-policy-svc** — Same pattern, `service: policy-svc, context: ./policy-svc, image_name: nebula-dns-policy-svc`

7. **build-dnsdist** — Same pattern, `service: dnsdist, context: ./dnsdist, image_name: nebula-dns-dnsdist`

8. **build-unbound** — Same pattern, `service: unbound, context: ./config/unbound, image_name: nebula-dns-unbound`

9. **deploy-staging** — Deploy to staging after all builds
   - `needs: [build-api, build-ui, build-admin-ui, build-policy-svc, build-dnsdist, build-unbound]`
   - `environment: staging`
   - `runs-on: ubuntu-latest`
   - Steps:
     a. `actions/checkout@v4`
     b. `digitalocean/action-doctl@v2` with DO token
     c. `doctl kubernetes cluster kubeconfig save ${{ secrets.DOKS_CLUSTER_ID_STAGING }}`
     d. Install Helm: use `azure/setup-helm@v4`
     e. Helm deploy:
        ```
        helm upgrade nebula-dns ./helm/safedns \
          --install \
          --namespace nebula-dns-staging \
          --create-namespace \
          --atomic \
          --wait \
          --timeout 10m \
          --history-max 10 \
          --set global.imageRegistry=${{ env.DOCR_REGISTRY }} \
          --set api.image.tag=${{ github.sha }} \
          --set ui.image.tag=${{ github.sha }} \
          --set adminUi.image.tag=${{ github.sha }} \
          --set policySvc.image.tag=${{ github.sha }} \
          --set dnsdist.image.tag=${{ github.sha }} \
          --set unbound.image.tag=${{ github.sha }} \
          -f ./helm/safedns/values-staging.yaml
        ```
     f. Verify deployment health:
        ```
        kubectl rollout status deployment/api -n nebula-dns-staging --timeout=5m
        kubectl rollout status deployment/ui -n nebula-dns-staging --timeout=5m
        kubectl rollout status deployment/admin-ui -n nebula-dns-staging --timeout=5m
        ```
     g. Output deployment summary to `$GITHUB_STEP_SUMMARY`

10. **deploy-production** — Deploy to production with manual approval
    - `needs: deploy-staging`
    - `if: github.ref == 'refs/heads/main'` (only from main branch)
    - `environment: production` (configured with required reviewers in repo settings)
    - `runs-on: ubuntu-latest`
    - Steps:
      a. `actions/checkout@v4`
      b. `digitalocean/action-doctl@v2` with DO token
      c. `doctl kubernetes cluster kubeconfig save ${{ secrets.DOKS_CLUSTER_ID_PRODUCTION }}`
      d. Install Helm: `azure/setup-helm@v4`
      e. Helm deploy:
         ```
         helm upgrade nebula-dns ./helm/safedns \
           --install \
           --namespace nebula-dns \
           --atomic \
           --wait \
           --timeout 15m \
           --history-max 10 \
           --set global.imageRegistry=${{ env.DOCR_REGISTRY }} \
           --set api.image.tag=${{ github.sha }} \
           --set ui.image.tag=${{ github.sha }} \
           --set adminUi.image.tag=${{ github.sha }} \
           --set policySvc.image.tag=${{ github.sha }} \
           --set dnsdist.image.tag=${{ github.sha }} \
           --set unbound.image.tag=${{ github.sha }} \
           -f ./helm/safedns/values-production.yaml
         ```
      f. Verify deployment health (all services)
      g. Run smoke test: kubectl exec to curl API health endpoint
      h. Output deployment summary to `$GITHUB_STEP_SUMMARY`

**Important notes:**
- Use `if: always() && (needs.run-tests.result == 'success' || inputs.skip_tests)` pattern for builds to handle both normal and emergency flows
- Production timeout is 15m (longer than staging 10m) per research recommendation
- Both staging and production use `--atomic` for automatic rollback on failure
- `--history-max 10` limits Helm release history to prevent etcd bloat
- Add copyright header matching project convention

**Permissions needed:**
```yaml
permissions:
  contents: read
  actions: read
```
