<objective>
Configure HPA with custom DNS query metrics for Policy Service auto-scaling and create automated backup verification for PostgreSQL and ClickHouse.

Purpose: CPU-based scaling doesn't correlate well with DNS query load — a pod can handle high QPS at low CPU due to in-memory cache lookups. Custom DNS QPS metrics enable scaling based on actual workload. Backup verification prevents the "untested backups aren't backups" anti-pattern.

Output: Prometheus Adapter configuration for custom metrics, enhanced Policy Service HPA, backup verification script and CronJob.
</objective>

**Prometheus Adapter Configuration (k8s/base/monitoring/prometheus-adapter-config.yaml):**

Create a new ConfigMap for Prometheus Adapter custom metric rules. This configures the adapter to query Prometheus for `dns_queries_total` (counter metric exposed by policy-svc at /metrics) and expose it as `dns_queries_per_second` rate metric to the Kubernetes custom metrics API.

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: prometheus-adapter-config
  namespace: monitoring
  labels:
    app: prometheus-adapter
data:
  config.yaml: |
    rules:
      - seriesQuery: 'dns_queries_total{namespace="nebula-dns",job="policy-svc"}'
        resources:
          overrides:
            namespace: {resource: "namespace"}
            pod: {resource: "pod"}
        name:
          matches: "^(.*)_total$"
          as: "${1}_per_second"
        metricsQuery: 'sum(rate(<<.Series>>{<<.LabelMatchers>>}[2m])) by (<<.GroupBy>>)'
      - seriesQuery: 'policy_evaluation_duration_seconds_count{namespace="nebula-dns",job="policy-svc"}'
        resources:
          overrides:
            namespace: {resource: "namespace"}
            pod: {resource: "pod"}
        name:
          as: "policy_evaluations_per_second"
        metricsQuery: 'sum(rate(<<.Series>>{<<.LabelMatchers>>}[2m])) by (<<.GroupBy>>)'
```

**Backup Verification Script (scripts/verify-backups.sh):**

Create a comprehensive backup verification script that tests both PostgreSQL and ClickHouse backup integrity. The script should:

1. **PostgreSQL PITR Verification:**
   - Connect to managed PostgreSQL using `$POSTGRES_HOST`, `$POSTGRES_USER`, `$POSTGRES_PASSWORD`, `$POSTGRES_DB` env vars
   - Query production row counts for key tables: tenants, users, policies, locations
   - Log results with timestamps
   - Note: DigitalOcean Managed PostgreSQL handles PITR automatically — verification confirms data accessibility and consistency, not physical backup file integrity. The script validates that a point-in-time snapshot can be queried and returns expected data.

2. **ClickHouse Cloud Backup Verification:**
   - Connect to ClickHouse Cloud using `$CLICKHOUSE_HOST`, `$CLICKHOUSE_USER`, `$CLICKHOUSE_PASSWORD`, `$CLICKHOUSE_DB` env vars
   - Query table existence and row counts for: dns_queries, threat_logs, audit_logs
   - Verify partitioning is active (check system.parts for recent partitions)
   - Log results with timestamps

3. **Verification Output:**
   - Print summary with pass/fail status for each check
   - Exit with code 0 if all checks pass, 1 if any fail
   - Format output for easy parsing in CI/Kubernetes logs

Include copyright header. Make script executable (`chmod +x`).
