Add three new rule groups to the existing prometheus-rules.yaml file (keep all existing rules intact):

**1. DNS Availability SLO group (`nebula-dns-slo-availability`):**

SLO target: 99.9% availability = 0.1% error budget = 43.8 minutes/month

Fast burn alert (`DNSAvailabilitySLOFastBurn`):
- severity: critical
- Multi-window: 1h long window AND 5m short window
- Burn rate: 14.4x (exhausts budget in ~2 days)
- Expression: error rate from `probe_success{job="blackbox-dns"}` metrics (from Blackbox Exporter, Plan 31-03)
- `for: 2m` to avoid single-sample spikes
- Annotations: summary, description with budget exhaustion timeframe

Slow burn alert (`DNSAvailabilitySLOSlowBurn`):
- severity: warning
- Multi-window: 6h long window AND 30m short window
- Burn rate: 6x (exhausts budget in ~5 days)
- `for: 15m`
- Same metric source as fast burn

Also add API error rate burn alerts (`APIAvailabilitySLOFastBurn`, `APIAvailabilitySLOSlowBurn`):
- Same multi-window pattern but using `http_requests_total{job="api",status=~"5.."}` metrics
- Same burn rates (14.4x fast, 6x slow)

**2. Latency SLO group (`nebula-dns-slo-latency`):**

API latency alert (`APILatencySLOFastBurn`):
- severity: critical
- Multi-window: 1h AND 5m
- Expression: `histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket{job="api"}[WINDOW])) by (le)) > 0.2` (200ms threshold)
- `for: 2m`

API latency slow burn (`APILatencySLOSlowBurn`):
- severity: warning
- Multi-window: 6h AND 30m
- Same expression, `for: 15m`

Policy eval latency alert (`PolicyEvalLatencySLOFastBurn`):
- severity: critical
- Multi-window: 1h AND 5m
- Expression: `histogram_quantile(0.95, sum(rate(policy_evaluation_duration_seconds_bucket{job="policy-svc"}[WINDOW])) by (le)) > 0.05` (50ms threshold)
- `for: 2m`

Policy eval slow burn (`PolicyEvalLatencySLOSlowBurn`):
- severity: warning
- Multi-window: 6h AND 30m
- `for: 15m`

**3. Connection pool exhaustion group (`nebula-dns-connection-pool`):**

PostgreSQL pool alert (`PostgresConnectionPoolExhaustion`):
- severity: critical
- Expression: `pg_stat_activity_count{job="postgres"} / pg_settings_max_connections{job="postgres"} > 0.9` (>90% usage)
- `for: 5m`

Redis connection alert (`RedisConnectionPoolExhaustion`):
- severity: warning
- Expression: `redis_connected_clients{job="redis"} / redis_config_maxclients{job="redis"} > 0.8` (>80% usage)
- `for: 5m`

Also update the existing `APIHighLatency` threshold from `> 1` (1 second) to `> 0.5` (500ms) to be more useful as an info-level alert (the SLO burn rate alerts handle the critical/warning paging). Change its severity from `warning` to `info`.

Add SLO labels to all new rules: `slo: dns_availability`, `slo: api_availability`, `slo: api_latency`, `slo: policy_latency` respectively.

Add copyright comment at top of file.
