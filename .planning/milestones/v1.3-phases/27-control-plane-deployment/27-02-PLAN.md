Refactor both UI and Admin UI to use runtime environment variables instead of NEXT_PUBLIC_ prefix for configuration that varies per environment (API URL, App URL, Admin UI URL).

Purpose: NEXT_PUBLIC_ variables are baked into JavaScript bundles at build time, making Docker images environment-specific. By using server-side env vars exposed via /api/config endpoints, a single Docker image works across all environments (staging, production).

Output: Both UIs use runtime configuration for environment-specific values, enabling multi-environment Docker image reuse.
</objective>

**Step 2: Refactor `ui/src/lib/api.ts`**

Replace the top-level `NEXT_PUBLIC_API_URL` constant with a cached config fetcher pattern:

```typescript
// Nebula DNS - API Client Configuration
// Runtime configuration fetched from /api/config endpoint
// Copyright (c) 2026 Jeremy McSpadden <jeremy@fluxlabs.net>

let cachedConfig: { apiUrl: string; appUrl: string; adminUiUrl: string } | null = null;

export async function getConfig() {
  if (cachedConfig) return cachedConfig;

  // In server components, read directly from process.env
  if (typeof window === 'undefined') {
    cachedConfig = {
      apiUrl: process.env.API_URL || 'http://localhost:4010',
      appUrl: process.env.APP_URL || 'http://localhost:4011',
      adminUiUrl: process.env.ADMIN_UI_URL || 'http://localhost:4012',
    };
    return cachedConfig;
  }

  // In client components, fetch from /api/config
  try {
    const res = await fetch('/api/config');
    cachedConfig = await res.json();
    return cachedConfig!;
  } catch {
    // Fallback for development
    cachedConfig = {
      apiUrl: 'http://localhost:4010',
      appUrl: 'http://localhost:4011',
      adminUiUrl: 'http://localhost:4012',
    };
    return cachedConfig;
  }
}

// Synchronous accessor for cases where config is already loaded
// Falls back to /api/config fetch if not yet loaded
let apiUrlCache: string | null = null;

export function getApiUrl(): string {
  if (apiUrlCache) return apiUrlCache;

  // Server-side: read directly
  if (typeof window === 'undefined') {
    return process.env.API_URL || 'http://localhost:4010';
  }

  // Client-side: return default, then update asynchronously
  getConfig().then(c => { apiUrlCache = c.apiUrl; });
  return 'http://localhost:4010'; // Will be replaced after first fetch
}
```

IMPORTANT: The above synchronous pattern has a race condition. Instead, use this simpler approach — keep the existing export pattern but change the source:

```typescript
// For the main UI, the cleanest approach is to have an initialization step.
// Since most API calls go through useApi.ts hook, update that hook to resolve config first.
```

**REVISED APPROACH — simpler and more reliable:**

1. Keep `ui/src/lib/api.ts` as a simple module-level constant, but source it from the /api/config response. Since this file is imported everywhere, the constant will be initialized once. For SSR, `process.env.API_URL` works. For CSR, we need the config fetch.

The simplest approach that minimizes refactoring:

In `ui/src/lib/api.ts`, change:
```typescript
const API_URL = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:4000'
```
to:
```typescript
const API_URL = process.env.API_URL || process.env.NEXT_PUBLIC_API_URL || 'http://localhost:4010'
```

This works because:
- Server-side: `process.env.API_URL` is available at runtime
- Client-side: `process.env.NEXT_PUBLIC_API_URL` is baked in at build time as fallback
- The NEXT_PUBLIC_ fallback ensures backward compatibility during migration

Then create the `/api/config` route for client-side components that need the URL dynamically. And update `useApi.ts` to fetch from `/api/config` on mount:

In `ui/src/hooks/useApi.ts`, wrap the existing hook with config resolution:
- Add a module-level `let apiUrl: string | null = null;`
- On first call, fetch `/api/config` to populate `apiUrl`
- Use `apiUrl` for subsequent calls

**FINAL APPROACH — pragmatic dual-source:**

The cleanest migration path is:
1. Create `/api/config` route that exposes runtime env vars
2. Update `ui/src/lib/api.ts` to use `process.env.API_URL` with `process.env.NEXT_PUBLIC_API_URL` as fallback
3. In each file that directly references `process.env.NEXT_PUBLIC_API_URL`, replace with the imported constant from `ui/src/lib/api.ts` (many files already duplicate the env var lookup instead of importing)
4. Keep `NEXT_PUBLIC_API_URL` in `.env.example` for local development (baked at build time), but production Docker images use `API_URL` at runtime
