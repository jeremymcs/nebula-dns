**Core Value:** Get the platform tested, deployed on DigitalOcean, and handling real DNS traffic

## v1.3 Requirements

Requirements for production readiness milestone. Each maps to roadmap phases.

### Deployment & Infrastructure

- [x] **DEPLOY-01**: DOKS cluster provisioned with 3+ nodes running Kubernetes 1.30+
- [x] **DEPLOY-02**: Managed PostgreSQL provisioned with PgBouncer connection pooling and SSL
- [x] **DEPLOY-03**: Managed Valkey provisioned with TLS and password auth (replacing Redis)
- [x] **DEPLOY-04**: ClickHouse Cloud provisioned with environment-aware schema (MergeTree, not Replicated)
- [x] **DEPLOY-05**: API deployed as Deployment with Helm, connecting to managed PostgreSQL via PgBouncer
- [x] **DEPLOY-06**: Policy Service deployed as Deployment connecting to managed Valkey and ClickHouse Cloud
- [x] **DEPLOY-07**: Unbound deployed as StatefulSet with persistent cache volumes
- [x] **DEPLOY-08**: dnsdist deployed as Deployment with dual LoadBalancers (dns1, dns2) for DNS failover
- [x] **DEPLOY-09**: UI and Admin UI deployed with runtime environment variables (not NEXT_PUBLIC_ build-time)
- [x] **DEPLOY-10**: cert-manager configured with Let's Encrypt DNS-01 ACME for wildcard TLS certificates
- [x] **DEPLOY-11**: external-dns configured to sync LoadBalancer IPs to DigitalOcean DNS records
- [x] **DEPLOY-12**: Kubernetes Secrets created for all credentials with documented rotation procedure
- [x] **DEPLOY-13**: Database migrations run automatically via Helm pre-install/pre-upgrade hooks

### Testing

- [x] **TEST-01**: API unit tests expanded to cover admin modules (phases 19-21: user management, billing, alerting)
- [x] **TEST-02**: API integration tests using Testcontainers with real PostgreSQL, Redis, and ClickHouse
- [x] **TEST-03**: API E2E tests covering all critical endpoint flows (auth, admin, billing, MSP, impersonation)
- [x] **TEST-04**: UI E2E tests expanded from 20 to 60+ Playwright specs covering admin, MSP, and billing flows
- [x] **TEST-05**: Go policy-svc unit tests with table-driven patterns for policy evaluation
- [x] **TEST-06**: Go policy-svc integration tests validating Redis cache and ClickHouse logging
- [x] **TEST-07**: Load testing baseline established with k6 against DOKS staging (DNS and API endpoints)
- [x] **TEST-08**: Test assertion density enforced (>3 assertions per test, no toBeDefined()-only tests)

### Operations

- [x] **OPS-01**: Liveness and readiness probes configured for all services (exec-based for DNS services)
- [x] **OPS-02**: Graceful shutdown with SIGTERM handling and connection draining for all services
- [x] **OPS-03**: CI/CD pipeline: build, test, push to DO Container Registry, deploy to staging (auto), production (manual)
- [x] **OPS-04**: Incident runbooks created for DNS down, DB down, Redis down, policy-svc crash, cert expiration
- [x] **OPS-05**: Prometheus alerting rules configured for query success rate, policy eval latency, connection pool exhaustion
- [x] **OPS-06**: SLO tracking dashboards in Grafana (99.9% DNS availability, p95 latency targets)
- [x] **OPS-07**: Synthetic monitoring deployed (external probe sending DNS queries from multiple regions)
- [x] **OPS-08**: HPA configured with custom DNS query metrics for policy-svc auto-scaling
- [x] **OPS-09**: Backup verification — PostgreSQL PITR and ClickHouse Cloud automated backups confirmed working
- [x] **OPS-10**: Production deployment and rollback runbook documented

## Out of Scope

| Feature | Reason |
|---------|--------|
| Multi-cloud deployment | Premature optimization, DigitalOcean sufficient for 1-10 tenants |
| Custom CI/CD platform | GitHub Actions sufficient, don't reinvent |
| Self-hosted monitoring stack | Use managed services to reduce ops burden |
| Zero-downtime database migrations | Brief maintenance windows acceptable at current scale |
| Geo-distributed DNS resolution | Single region handles 100K-999K queries/day |
| Machine learning anomaly detection | Insufficient data at current scale, need 6+ months |
| Feature flags for every feature | Use only for deployment strategies |
