## v1.2 Requirements

Requirements for v1.2 milestone: Admin Roles & Alerting.

### RBAC

- [x] **RBAC-01**: Admin entity has role column (super_admin, admin, viewer)
- [x] **RBAC-02**: AdminRolesGuard validates role against required roles per endpoint
- [x] **RBAC-03**: @AdminRoles() decorator specifies required roles on controllers
- [x] **RBAC-04**: Admin JWT contains role claim for frontend permission checks
- [x] **RBAC-05**: All /admin/* endpoints have role requirements defined
- [x] **RBAC-06**: UI displays admin's current role in header/profile
- [x] **RBAC-07**: UI navigation filters menu items based on role permissions
- [x] **RBAC-08**: Viewer role has read-only access (403 on mutating actions)
- [x] **RBAC-09**: Server rejects self-role-escalation attempts with 403
- [x] **RBAC-10**: Break-glass Super Admin account exists before enforcement

### Admin User Management

- [x] **USER-01**: Super Admin can view list of all admin users with roles
- [x] **USER-02**: Super Admin can invite new admin via email with role assignment
- [x] **USER-03**: Invite tokens are hashed, expire after 7 days
- [x] **USER-04**: Invited admin can accept and set password/MFA
- [x] **USER-05**: Super Admin can view admin profile details
- [x] **USER-06**: Super Admin can suspend admin (blocks login)
- [x] **USER-07**: Super Admin can reactivate suspended admin
- [x] **USER-08**: Super Admin can reset another admin's MFA
- [x] **USER-09**: MFA reset sends notification email to target admin
- [x] **USER-10**: Admin activity log captures auth, management, and sensitive actions
- [x] **USER-11**: Super Admin can view pending invites with expiry status
- [x] **USER-12**: Super Admin can revoke pending invites

### Alerting Integrations

- [x] **ALERT-01**: Slack webhook can be configured with channel URL
- [x] **ALERT-02**: PagerDuty routing key can be configured
- [x] **ALERT-03**: Alert configs are encrypted at rest
- [x] **ALERT-04**: System health issues trigger alerts (service down, high error rate)
- [x] **ALERT-05**: Billing issues trigger alerts (payment failures)
- [x] **ALERT-06**: Security events trigger alerts (failed logins, suspicious impersonation)
- [x] **ALERT-07**: Critical alerts route to PagerDuty, warnings to Slack only
- [x] **ALERT-08**: Admin can enable/disable each integration independently
- [x] **ALERT-09**: Admin can send test alert to verify configuration
- [x] **ALERT-10**: PagerDuty uses consistent dedup_key format to prevent incident explosion

### Migration & Rollout

- [x] **ROLL-01**: Feature flag controls RBAC enforcement (ADMIN_RBAC_ENABLED)
- [x] **ROLL-02**: Shadow mode logs would-be denials without enforcing
- [x] **ROLL-03**: Migration script assigns Super Admin to designated admin
- [x] **ROLL-04**: Documentation for admin communication before enforcement
- [x] **ROLL-05**: Monitoring for increased 403 responses post-enforcement

## Out of Scope

| Feature | Reason |
|---------|--------|
| Custom role builder | 3-role hierarchy sufficient for 2-5 person team |
| Per-MSP alerting rules | Alerting is for ops team, not per-tenant |
| Real-time collaboration | Ops team uses existing tools (Slack) |
| Alert history UI | Start simple, add if needed based on usage |
| Admin profile photos | Non-essential for internal tool |
